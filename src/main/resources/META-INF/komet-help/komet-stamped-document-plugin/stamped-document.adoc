= The STAMPed Document card

The STAMPed Document card shows an AsciiDoc document that is kept in git, as the knowledge base holds it.
Every line carries the STAMP of the commit that wrote it: who wrote it, when, and on which path.
You can read the document, see where each line came from, review lines, and edit it.

To show your first document, see xref:opening-a-document.adoc[Opening an AsciiDoc document].

== The toolbar

From left to right:

Document chooser:: The documents the knowledge base holds. Choose one to show it. It says _No documents_ until a document has been opened.
Views:: How the document is shown. _Source_ shows it as lines, each with its number, the STAMP that introduced it and any annotation mark. A STAMP's identicon is drawn on the first line of each run of lines it introduced, and a bar in its colour runs down the rest of the run. Lines wider than the card scroll sideways together, with one scrollbar at the bottom of the card. _Reading_ shows it as a document, with each block's date in the left margin and its STAMPs in the right. A date or a STAMP is drawn where it differs from the block above; point at a block to see the ones it shares with the block above. In both views the header shows the date and the STAMPs of whatever is at the top of the card. _Page layout_ shows it on pages, as Print to PDF makes them. _Graph_ shows it as the knowledge base holds it: its sections and blocks, their lines and the references in them, each with its STAMP.
Modes:: Shown with the Graph view only. _Latest_ shows the document as it stands. _History_ adds each line's earlier versions and the lines later commits retired. _DocBook_ shows it as DocBook elements.
Layer:: What is drawn over the text: marginalia, commit tints, the review queue and annotation marks.
More:: The verbs that act on the whole document, described below.

When the card is wide, each control shows its name beside its icon. When it is narrow, only the icon shows; hover over it to see its name.

== The More menu

Open file…:: Chooses a committed `.adoc` file and shows it, materializing it first if the knowledge base lacks it.
Refresh:: Reads the list of documents and the shown document again.
Export…:: Writes the document from the knowledge base back into a working tree at its recorded path, and compares it with HEAD.
Print to PDF…:: Typesets the document, with the documents it includes, through your installed Typst.
Materialize:: Writes the commits of the shown file that the knowledge base lacks.
Materialize All:: Does the same for the file and every file it includes.
Rebuild from Git:: Drops the document from the knowledge base and materializes it again. Only ephemeral documents can be rebuilt; see xref:kinds-of-data.adoc[Kinds of data].
Remove Superseded Documents:: Deletes older copies of documents that were materialized again in the current form.
Show history:: Lists the STAMPs of the selected lines, or of the whole document, in order.
Go to page…:: Scrolls the Page layout to a page.

== Reviewing and editing

Click in a block to give it the focus. The Reading view marks the block with a bar at its left edge.
Drag across words to select them, or double-click one word.

A judgment is recorded on whole lines of the source, because a line is what carries a STAMP.
Right-click and choose _Affirm…_, _Refute…_ or _Comment…_ to record your judgment of the lines your selection touches; with no words selected the menu shows those lines selected.
Shift-click outside your selection to select every line from where it began to the line you click.
A judgment is a commit in the document's repository, signed or unsigned, and stays with the lines until the text they judge changes.

To mark words, select them in the Reading view, in Page layout or in the Source view.
A bar of marks appears where you finished selecting: bold, italic, underline, strike through, monospace, highlight and link.
Each mark has a key, which its button shows when you hover over it, and the same marks are under _Format_ on the right-click menu.
Choosing a mark the words already have removes it.
_Link_ opens the block's source in the Reading view with the address selected, for you to type.
Marks are written in a paragraph, a list item or an admonition.

To change the words themselves, right-click a block in the Reading view and choose _Edit block_.
A mark or an edit is saved at once, and is pending until you commit it.

== Committing your edits

While an edit is pending, a bar shows at the bottom of the card, above the status line.
It says how many lines are edited, for example _3 lines edited_.
When nothing is pending the bar is not there.

Message:: A line that says what the edit is for, such as _Mark the dose bold_. You can leave it empty. The commit then names the document and lists what changed.
Sign:: Signs the commit with your key, so that it can be shown to be yours. The card remembers your choice, and your annotations follow it.
Commit:: Writes the document with your edits into its folder and records them there as your own git commit. Pressing Enter in the message does the same. Nothing is pushed.
Discard…:: Asks whether to discard the edited lines, and says how many there are. If you agree, the document reads as it was last committed.
Restore as pending:: Shows after you discard an edit, or after a commit leaves part of an edit out. It brings that edit back as a pending edit.

When the edits are in more than one document, as with a document and one it includes, each _Commit_ records one document.
The bar stays until every document is committed.

If the document's file was also changed outside Komet, _Commit_ first asks about that file in a dialog, because you choose which changed file the commit holds.
_Commit…_ in the Repository panel opens the same dialog.
